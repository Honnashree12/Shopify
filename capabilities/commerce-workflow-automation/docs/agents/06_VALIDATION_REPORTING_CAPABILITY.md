# Validation Reporting Capability

## Type
Supporting Capability

## Purpose
The Validation Reporting Capability generates executive-ready PDF audit reports for Shopify product launch readiness audits. It aggregates evaluation metrics from the 53-check storewide validation engine, separates failed Blocker rules from Warning rules into dedicated tables, calculates launch scores, integrates remediation recommendations, and formats customized documents for team assignments and executive reviews.

## What It Does
1. Processes product validation results generated by the storewide validation suite.
2. Filters product catalog datasets based on selected product IDs, handles, or titles for targeted team assignment.
3. Formats executive summary boxes showing total active products audited, average launch score, launch ready count, launch blocked count, total failed blockers, and total warnings.
4. Generates per-product audit cards displaying product name, Shopify ID, handle, category, launch status badge (`READY TO LAUNCH` vs `LAUNCH BLOCKED`), score, blocker count, and warning count.
5. Builds separate **BLOCKER FAILURES** tables and **WARNING FAILURES** tables detailing Rule ID, Rule Name, Why Failed, Current State, and Suggested Deterministic Fix.
6. Integrates with `RemediationEngine` (`generate_remediations_for_product`) to populate exact proposed fix values and remediation logic into report tables.
7. Produces downloadable, publication-grade PDF documents using ReportLab platypus flowables.

## How It Works
1. **Product Filtering & Target Selection (`generate_validation_pdf_report`)**:
   - Accepts a list of product validation result dictionaries and optional `selected_identifiers`.
   - Normalizes product IDs, titles, and handles to filter target products; falls back to all products if no identifiers match.
2. **Document & Style Initialization**:
   - Creates a ReportLab `SimpleDocTemplate` configured with standard letter page size and 36pt margins.
   - Defines a cohesive color palette: Dark Slate (`#1e293b`), Brand Blue (`#2563eb`), Body Text (`#0f172a`), Muted Gray (`#64748b`), Blocker Red (`#dc2626`), Ready Green (`#16a34a`), and Amber Warning (`#d97706`).
   - Configures typography hierarchy styles for document title, metadata subtitle, section headings, body text, table headers, and table cell formatting.
3. **Flowable Story Building**:
   - **Header Banner**: Renders title, generation timestamp, optional assignee name (e.g. "Rachana"), and audit scope.
   - **Executive Summary Box**: Renders a 4-column summary metric table enclosed in a styled slate box.
   - **Per-Product Cards**: For each product, generates a header card displaying product metadata and status.
   - **Remediation Mapping**: Invokes `generate_remediations_for_product(product)` to map rule IDs to deterministic fixes.
   - **Blocker & Warning Tables**: Constructs separate styled tables for Blocker failures and Warning failures with clear red/amber accent headers.
4. **PDF Compilation**:
   - Compiles the flowable story into an in-memory `io.BytesIO` byte buffer or directly to a target file path and returns binary PDF bytes.

## Inputs
- `products`: List of product validation result dictionaries containing product attributes, scores, launch statuses, and 53-check rule evaluation maps.
- `selected_identifiers`: Optional list of string product IDs, titles, or handles to filter report scope.
- `assignee_name`: Optional string name of the team member assigned to resolve identified issues.
- `output_filename_or_stream`: Optional file path string or stream object for direct file saving.

## Outputs
- `bytes`: Complete binary PDF file content containing formatted audit summary, product scorecards, blocker tables, and warning tables.

## Important Business Rules
- **Separate Blocker and Warning Tables**: Blocker failures (critical launch-stopping errors) MUST be presented in a distinct table separate from Warning failures to give reviewers immediate clarity on launch blockers.
- **Remediation Integration**: Report failure tables MUST include suggested deterministic fixes generated by `remediation_engine.py` rather than displaying unhelpful raw error strings.
- **Active Products Scope Only**: Executive summary metric counts reflect active products in the audit scope.
- **Read-Only Reporting**: PDF report generation is entirely read-only and causes zero side effects on live Shopify stores or database configurations.

## Safety Boundaries
- **In-Memory Streaming**: Supports returning PDF output directly as byte streams (`io.BytesIO`) for web API downloads without requiring persistent disk writes.
- **Graceful Text Wrapping**: All table cell text is wrapped in ReportLab `Paragraph` flowables to prevent text clipping or margin overflowing on multi-page PDF renders.
